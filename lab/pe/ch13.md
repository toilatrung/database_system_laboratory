## 13.3
Consider the relations *section* and *takes*. Give an example instance of the two relations with three sections, each having five students. Then give a file structure for these relations that uses multitable clustering.

## 13.4
Consider a free-space map kept as a bitmap with two bits per block of the file: the bits are 00 if the block is 0–30 percent full, 01 if 30–60 percent full, 10 if 60–90 percent full, and 11 if more than 90 percent full. Such bitmaps fit in memory even for very large files.

### a
Give two benefits and one drawback of using two bits per block instead of one byte per block as described earlier in the chapter.

### b
Explain how the bitmap is kept up to date when records are inserted and deleted.

### c
Explain the advantage of the bitmap technique over free lists, both for searching for free space and for updating free-space information.

## 13.5
We must be able to determine quickly whether a block is in the buffer and, if it is, where in the buffer it is. Since database buffers are very large, which in-memory data structure would you use for this?

## 13.6
Suppose your university has accumulated a very large number of *takes* records over many years. Explain how the *takes* relation could be partitioned and what benefits partitioning could bring. Also explain one possible drawback of the technique.

## 13.7

### a
MRU is preferable to LRU.

### b
LRU is preferable to MRU.

## 13.8
PostgreSQL usually keeps a small buffer of its own and leaves the rest of main memory to the operating system’s buffer manager for file-system buffering. Explain (a) the benefit of this approach and (b) one key limitation of it.
