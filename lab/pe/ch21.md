# Chapter 21 — Parallel and Distributed Storage

## 21.1
For a range selection on a range-partitioned attribute, it may happen that only one disk has to be accessed. Describe the advantages and disadvantages of this property.

## 21.2
Recall that histograms are used to build load-balanced range partitions.

### a
A histogram covers values 1 to 100, split into the 10 ranges 1–10, 11–20, …, 91–100, whose frequencies are, in order, 15, 5, 20, 10, 10, 5, 5, 20, 5, and 5. Give a load-balanced range-partitioning function that splits the values into five partitions.

### b
Write an algorithm that computes a balanced range partitioning with p partitions, given a histogram of frequency distributions with n ranges.

## 21.3
Histograms are usually built on the values of a particular attribute (or set of attributes) of a relation. Such histograms help avoid data-distribution skew but are of little use for avoiding execution skew. Explain why.

Now suppose you have a workload of queries that do point lookups. Explain how the queries of the workload can be used to design a partitioning scheme that avoids execution skew.

## 21.4
Replication:

### a
Give two reasons for replicating data across geographically distributed data centers.

### b
Centralized databases support replication by means of log records. How does replication in centralized databases differ from replication in parallel/distributed databases?

## 21.5
Parallel indices:

### a
In a centralized database, secondary indices store the record identifier. A global secondary index could likewise store the number of the partition that holds the record together with a record identifier inside that partition. Why would this be a bad idea?

### b
Global secondary indices are implemented much like the local secondary indices used when records are stored in a B<sup>+</sup>-tree file organization. Explain what the two situations have in common that leads to a similar implementation of the secondary indices.

## 21.6
Parallel database systems keep replicas of every data item (or partition) on more than one node.

### a
Why is it better to spread the copies of the data items assigned to a node over several other nodes, rather than keeping all of those copies on the same node (or set of nodes)?

### b
What are the advantages and disadvantages of using RAID storage instead of storing an extra copy of every data item?

## 21.7
Partitioning and replication.

### a
Explain why range partitioning gives better control over tablet sizes than hash partitioning. Draw an analogy between this situation and B<sup>+</sup>-tree indices versus hash indices.

### b
Some systems first hash the key and then apply range partitioning to the hash values. What could motivate this choice, and what are its disadvantages compared with range partitioning directly on the key?

### c
Data can be partitioned horizontally and then partitioned vertically locally at each node. The opposite is also possible: partition vertically first, then partition each vertical fragment horizontally on its own. What are the benefits of the first option over the second?

## 21.8
To send a request to the master replica of a data item, a node must know which replica is currently the master for that item.

### a
Suppose that after a node determines which node is the master replica of a data item, but before its request arrives there, mastership changes and another node becomes the master. How can this situation be handled?

### b
The master replica can be chosen per partition, but some systems support a per-record master: the records of a partition (or tablet) are replicated on a set of nodes, and each record’s master may be any node of that set, independently of the masters of other records. Give two benefits of tracking the master per record.

### c
Suggest how the master replica of every record can be tracked when there is a very large number of records.
