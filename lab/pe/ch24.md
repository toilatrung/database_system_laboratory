# Chapter 24 — Advanced Indexing Techniques

## 24.1
LSM trees and buffer trees (Section 14.8.2) both help write-intensive workloads compared with ordinary B<sup>+</sup>-trees, and buffer trees can even give better lookup performance. Nevertheless, LSM trees are the ones more commonly used in Big Data settings. What is the main reason for this preference?

## 24.2
Consider the optimized technique for counting how many bits are set in a bitmap (using a precomputed array indexed by byte values). Keeping the cache size in mind, what are the tradeoffs between choosing a smaller and a larger array?

## 24.3
Suppose line segments are to be stored in an R-tree. When a segment is not parallel to the axes, its bounding box can be large and contain a lot of empty area.

- Describe how such large bounding boxes affect the performance of queries asking for the line segments that intersect a given region.
- Briefly describe a technique that improves the performance of such queries, and give an example of its benefit. (Hint: segments can be split into smaller pieces.)

## 24.4
Give an algorithm for searching an R-tree that efficiently finds the nearest neighbor of a given query point.

## 24.5
Give a recursive procedure that efficiently computes the spatial join of two relations that both have R-tree indices. (Hint: use bounding boxes to check whether leaf entries below a pair of internal nodes can possibly intersect.)

## 24.6
A file uses extendable hashing and holds records with these search-key values:

2, 3, 5, 7, 11, 17, 19, 23, 29, 31

Show the extendable hash structure for this file when the hash function is h(x) = x mod 8 and each bucket can hold three records.

## 24.8
Write pseudocode for deleting entries from an extendable hash structure, including the details of when and how buckets are coalesced. You need not handle shrinking the bucket address table.

## 24.9
Propose an efficient way to test whether the bucket address table of an extendable hash structure can be reduced in size, by keeping an extra count together with the table. Explain how this count is maintained when buckets are split, coalesced, or deleted. (Note: shrinking the bucket address table is expensive, and later inserts may make it grow again, so it is better not to shrink it as soon as it becomes possible, but only when the number of index entries has become small relative to the size of the bucket address table.)
