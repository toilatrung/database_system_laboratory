# Chapter 25 — Advanced Application Development

## 25.1
Find out all the performance information that your favorite database system provides. At a minimum look for: which queries are executing now or were executed recently; the resources (CPU and I/O) each of them consumed; what fraction of page requests caused buffer misses (per query, if available); and which locks are highly contended. Also obtain CPU, I/O, and network utilization, including the number of open network connections, using operating-system utilities.

## 25.2
Many applications need to generate a sequence number for every transaction.

### a
If a sequence counter is locked in a two-phase manner, it can become a concurrency bottleneck. Explain why.

### b
Many database systems offer built-in sequence counters that are not locked two-phase: when a transaction asks for a sequence number, the counter is locked, incremented, and immediately unlocked.

1. Explain how such counters can improve concurrency.
2. Explain why the sequence numbers of the transactions that finally commit may contain gaps.

## 25.3
You are given a relation r(a, b, c).

### a
Give an example of a situation in which the performance of equality selection queries on attribute a depends greatly on how r is clustered.

### b
Suppose there are also range selection queries on attribute b. Can r be clustered so that both the equality selections on r.a and the range selections on r.b are answered efficiently? Explain.

### c
If such a clustering is not possible, suggest how both kinds of queries can be executed efficiently by choosing suitable indices.

## 25.4
When a large number of records are inserted into a relation within a short time, a common recommendation is to drop all indices and recreate them after the inserts have finished.

### a
What is the motivation for this recommendation?

### b
Dropping and recreating indices can be avoided by bulk-updating them. Suggest how this can be done efficiently for B<sup>+</sup>-tree indices.

### c
Would this advice still make sense if the indices were write-optimized indices such as LSM trees?

## 25.5
A database application seems to have no single bottleneck: CPU and disk utilization are both high and all database queues are roughly balanced. Does this mean the application cannot be tuned any further? Explain.

## 25.6
A system runs three types of transactions. Type A transactions run at 50 per second, type B at 100 per second, and type C at 200 per second. The transaction mix is 25 percent type A, 25 percent type B, and 50 percent type C.

### a
Assuming no interference between transactions, what is the average transaction throughput of the system?

### b
Which factors can cause interference between transactions of different types, making the computed throughput incorrect?

## 25.7

```sql

from r natural left outer join s;
```

on relations r(A, B) and s(B, C), but wrote instead

```sql
select *
from r natural join s;
```

### a
Give sample data for r and s on which the two queries produce the same result.

### b
Give sample data for r and s on which the two queries produce different results, thereby exposing the mistake.
